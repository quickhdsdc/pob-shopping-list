# 设计简报 —— 给 Claude Design 用

这份文档是拿去做界面重新设计的输入。当前界面能用但不好看，需要重做视觉。
**功能逻辑不要改**，这里写清楚了每一块必须承载什么信息、为什么。

线上现状：https://poe-shopping-list.pob-shopping-list.workers.dev
代码：`src/index.html`（结构）、`src/styles.css`（样式）、`src/ui.ts`（卡片渲染）、
`src/copy.ts`（全部文案）

---

## 这个工具是干什么的

玩家在 poe.ninja 上看到一套心仪的配装，想照着买齐。

**输入**：一段 Path of Building 分享码（或 pobb.in / pastebin 链接）。
**输出**：这套 build 里**每一件装备**对应一条流放之路官方交易站的搜索链接，
数值门槛已经按容差放宽 —— 因为一比一复刻通常买不起。

一次典型的使用：粘贴 → 点生成 → 出来 23～44 张卡片 → 逐件点「Search」跳到交易站买。

**它不是什么**：不估价、不显示价格、不代查。只生成链接。

---

## 用户是谁

流放之路的老玩家。他们每天都在看交易站、poe.ninja、PoB 这类高密度的深色工具界面。
他们能读懂 `+134 to maximum Life` 这种原文，**不需要解释性的装饰**，需要的是一屏能塞下更多信息。

**明确要求：视觉风格要跟这几个站统一** —— poedb.tw、poe.ninja、poe.re。
用户的原话是「我的网站风格也要和他们统一」。它们的共性：深色为主、信息密度极高、
表格化、几乎没有装饰性留白、物品图标在每行左边、稀有度颜色到处用。

## 必须承载的信息

### 1. 输入区（粘贴之前）

- 一个大的粘贴框（PoB 代码是一串一万多字符的 base64，等宽字体）
- 四个全局参数：**赛季**（可搜索下拉，联网时自动填当前赛季）、**挂单类型**、
  **容差 %**、**每件最多筛几条**
- 主按钮：生成
- 一句话说明容差是什么（「80% 会把 +134 生命的词条搜成 ≥107」）
- 从哪拿到 build 代码的说明（PoB 里 Import/Export → Generate；poe.ninja 点 Copy build code；
  或者直接贴 pobb.in / pastebin 链接）

### 2. 结果区（同一页往下长，不是新页面）

**一条统计**：`44 items | 137 mods matched | 12 unrecognised`
—— 识别率要一眼能看出来，以前是一句流水账，得读完才知道。

**每件装备一张卡片**，卡片里有：

| 元素 | 说明 |
| --- | --- |
| 槽位 | `Weapon 1` / `Body Armour` / `Tree jewel · 55373` / `(not equipped)` |
| 物品名 | **按稀有度上色**，这是 PoE 的强惯例，见下面配色 |
| 底子 | 比如 `Slink Gloves`。传奇和稀有装备名字和底子是两行 |
| 词条表 | 每条一行 |
| 两个按钮 | Search（跳交易站）、Copy（复制链接） |
| 一句提示 | 说明这张卡默认勾了什么 |

**词条行**（这是信息密度最高的地方，44 件装备 × 每件 5～8 条）：

```
[✓]  14% increased Attack Speed                          ≥ [ 11 ]
[✓]  +16% to all Elemental Resistances      [Implicit]   ≥ [ 12 ]
[ ]  Socketed Attacks have +90% to Crit Multi            ≥ [ 72 ]     ← 没勾，划掉
[✗]  Curse Enemies with Punishment on Hit   [No filter]  not in the trade stat list
```

- **勾选框**：勾上才进搜索条件
- **词条原文**：等宽字体（玩家在游戏里看到的就是等宽）
- **`Implicit` 徽章**：植入词条要跟词缀区分
- **比较符 `≥` / `≤`**：负数词条（`-13 法力消耗`）越负越好，用上限
- **数值输入框**：可改
- **未识别的词条**：标红、勾选框禁用、给一句原因。**绝不静默丢掉** ——
  用户必须知道这条没进搜索

### 3. 特殊状态

- **底子没认出来**：卡片描红边 + 一行说明（新赛季的底子）
- **各种输入错误**：不是合法代码 / 链接读不到 / 浏览器太旧
- **导入中**：从链接取 build 的等待态
- **离线单文件版**：没有后端，赛季只能手填、链接导入不可用

---

## 硬约束

1. **必须支持浅色和深色两套**，跟随系统。玩家白天黑夜都在用。
2. **移动端要能看。** 44 张卡片的表格在手机上不能糊。
3. **没有构建时框架** —— 原生 DOM + 一个 CSS 文件。别用需要 React/Tailwind 的方案。
4. **两种产物共用同一套样式**：托管版和「下载下来双击即用」的离线单文件版。
   所以**字体和图形元素不能引外部资源** —— 系统字体或内联 SVG。
   **唯一的例外是装备图标**：它引 GGG 的 CDN，因此只有托管版有，离线版没有。
   这就是为什么「没有图标时布局不能塌」是硬要求，不是锦上添花。
5. **信息密度优先**。这是工具不是落地页，留白不能挤掉内容。

## 现在的视觉语言（可以推翻，但先知道为什么这么定）

### 稀有度配色 —— 这个别动

PoE 玩家对这四个颜色的条件反射比任何设计系统都强，游戏里、交易站上、所有社区站都一致：

| 稀有度 | 浅色 | 深色 |
| --- | --- | --- |
| 传奇 Unique | `#8d5117` | `#d08b4f` |
| 稀有 Rare | `#6f5f0c` | `#ddd06a` |
| 魔法 Magic | `#33409e` | `#93a0ea` |
| 普通 Normal | `#4a4f5a` | `#b6bcc7` |

### 其余的 token（`src/styles.css`）

深色：背景 `#13151a`，面板 `#1a1d24`，次级面板 `#20242c`，
正文 `#e3e6eb`，次要 `#98a0af`，更弱 `#6f7787`，分隔线 `#2a2f39`，
词条文本 `#9aa4d6`，强调 `#d08b4f`，成功 `#6cc08d`，错误 `#e07a6c`。

浅色：背景 `#e9eaee`，面板 `#f5f6f8`，正文 `#191c22`，分隔线 `#ccd1d9`，强调 `#8d5117`。

### 字体（全是系统字体，因为不能引外部资源）

- 标题和物品名：`"Iowan Old Style","Palatino Linotype",Palatino,Georgia,serif`
  —— 衬线是刻意的，对应游戏内物品 tooltip 的观感
- 正文：`"Segoe UI Variable Text","Segoe UI",system-ui,-apple-system,sans-serif`
- 词条文本：`"Cascadia Mono",Consolas,ui-monospace,monospace`

### 其它现有习惯

- 圆角 2～3px（工具感，不是圆润的消费级产品）
- 小标签：10.5px、字母间距 `.13em`、全大写、弱色
- 卡片：1px 边框 + 面板底色，`padding: 14px 16px`

## 明确的不满

用户原话：「你弄的有点丑」。我自己看到的问题：

- **整体太平**，全是同一层级的灰框套灰框，扫过去没有节奏
- **卡片头部**（槽位 / 名字 / 底子 / 按钮）挤在一起，层级不清楚
- **词条表就是四列对齐**，没有视觉引导，勾中和没勾中的区别只有划线
- **统计条**是后加的，跟上面的控件区没建立关系
- **没有任何图形元素** —— 全是文字和边框
- 稀有度颜色只用在物品名上，卡片本身没有体现

可以大胆推翻的：布局结构、密度节奏、卡片形态、勾选态的表达、
统计条的呈现、控件区的组织。

**不能推翻的**：稀有度配色的语义、词条原文用等宽、未识别词条必须显眼、
两套主题、无外部资源。

## 未来会加的东西（设计时留好位置）

- **装备图标**（数据已就绪，见 `PROGRESS.md`）。`data/icons.tsv` 已经生成，
  运行时拼成 `https://web.poecdn.com/image/<path>.png`。设计时按这几条来：

  - 位置：卡片左侧，跟槽位/物品名/底子那一栏并排
  - 尺寸：游戏原图是 1×1 到 2×4 格不等（`Slink Gloves` 是 2×2，`Carnal Armour` 是 2×3），
    **不是正方形**。别写死正方形容器，按最大边缩放、居中留白
  - **1088 条底子里 72 条没有图（6.6%），传奇只有底子的图，离线单文件版完全没有图。**
    这三种情况都得好看 —— 没图标时布局不能塌、不能留个空洞
- **中英切换**：一个语言切换控件。中文文案会更长，布局不能写死宽度。
